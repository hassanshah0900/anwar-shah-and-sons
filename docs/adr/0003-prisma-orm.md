# 0003. Prisma as the ORM

- **Status**: Superseded by [0009](0009-drizzle-orm.md)
- **Date**: 2026-11-01

## Context

The API needs type-safe access to PostgreSQL, versioned schema migrations, and a workflow
that is easy to run locally and in a deployment pipeline.

## Decision

Use Prisma 7 with:

- the `prisma-client` generator, emitting an ESM client into `apps/api/src/generated`
  (git-ignored, regenerated by the `db:generate` task);
- the `@prisma/adapter-pg` driver adapter, so queries go through the standard `pg` driver;
- `prisma migrate` for schema migrations committed to `apps/api/prisma/migrations`.

TypeORM was the main alternative. Prisma was preferred because its schema file is the
single source of truth for both the database and the generated types, and because its
migration workflow is straightforward to reason about.

## Consequences

- Query results are fully typed from the schema, with no hand-written entity classes.
- The client must be generated before type checking or building. Turborepo runs
  `db:generate` before those tasks.
- Raw SQL is still available for cases Prisma does not express well.
- The ORM is accessed only through `PrismaService`, keeping a single connection pool per
  process.
